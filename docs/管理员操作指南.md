# AI Learning Lab · 管理员操作指南

> 给这台电脑的所有者。只讲“要做的动作”，不讲架构。
> 项目目录：`D:\dsh_work\projects\ai-learning-lab`；数据在 `content/`，备份在 `backups/`。

## 0. 一分钟版

| 我想… | 做什么 |
| --- | --- |
| 本机自己用（改代码） | `npm run dev` → <http://127.0.0.1:3000> |
| 本机自己用（正式） | `npm run build` → `npm run start` |
| 让手机访问 | `npm run auth:set-password` → `npm run build` → `npm run start:lan` |
| 停止 | 在运行命令的终端按 `Ctrl+C` |
| 备份 | 页面 `/backup` → 右上角「立即备份」 |
| 恢复 | `/backup` → 对 zip 点「预览恢复」→ 勾选确认 → 输入「恢复」→「执行恢复」 |
| 改口令 / 踢掉所有设备 | `npm run auth:set-password`；要踢设备就加 `-- --rotate-session` |

> 在这台机器的 PowerShell 里，`npm` 可能先命中 `npm.ps1` 被“未签名脚本”拦住。
> 遇到就改用 `& 'D:\tools\nodejs\npm.cmd' run …`，效果一样。

## 1. 第一次（或换电脑后）跑起来

前置：Windows、Node.js 24.x（实测 24.21）、npm 11.x、Git；跑 E2E 还要系统 Chrome。

```powershell
cd D:\dsh_work\projects\ai-learning-lab
npm ci                    # 严格按 package-lock.json 装依赖
npm run build
npm run start             # 打开 http://127.0.0.1:3000
```

- 本机模式**不需要**口令，也不需要 `.env.local`。
- `content/` 不在仓库里，所以第一次打开知识库是空的 —— 这是正常的。
- 想先放点假数据看效果：把 `e2e/fixtures/content/` 里的内容复制到 `content/`，刷新即可。

## 2. 三种启动方式（别混用）

| 用途 | 命令 | 监听 | 说明 |
| --- | --- | --- | --- |
| 改代码 | `npm run dev` | `127.0.0.1:3000` | 热更新；不要拿它当正式服务 |
| 本机正式用 | `npm run build` → `npm run start` | `127.0.0.1:3000` | 手机连不上（故意的） |
| 手机 / 局域网 | `npm run build` → `npm run start:lan` | `0.0.0.0:3000` | 强制口令登录；没配置就拒绝启动 |

- 同一份 `content/` **同时只开一个实例**。两个实例（或一个 `next dev` 加一个 `next start`）一起写，进程内的写锁管不到。
- 停服务就是终端里 `Ctrl+C`；关掉终端窗口也算停。

## 3. 打开 / 关闭手机访问

### 打开

```powershell
# 1) 设一次口令（至少 8 位，输两次；只写 scrypt 哈希进 .env.local）
npm run auth:set-password

# 2) 局域网必须用生产构建
npm run build

# 3) 启动；终端会打印本机与局域网地址
npm run start:lan
```

1. 手机和电脑连**同一个 Wi-Fi**。
2. 手机浏览器打开终端里 `http://192.168.x.x:3000` 那一行（不是 `127.0.0.1`）。
3. 输入刚才设的口令。会话 12 小时；连续错 5 次锁 5 分钟。
4. 退出登录在 `/settings` 底部。

第一次连不上，按顺序查：

```powershell
# 以管理员身份开 PowerShell；只放行专用网络，不要关整个防火墙
New-NetFirewallRule -DisplayName "AI Learning Lab" -Direction Inbound -Protocol TCP -LocalPort 3000 -Action Allow -Profile Private
```

- 电脑和手机是不是同一网段（手机别开流量/VPN）。
- 防火墙里有没有 `node.exe` 的**入站 Block** 规则 —— Block 优先于 Allow，有就先删那条规则。
- 本机 `http://127.0.0.1:3000` 能不能开；能开说明服务没问题，是网络/防火墙。

### 关闭

- `Ctrl+C` 停掉 `start:lan`，再按需用 `npm run start` 或 `npm run dev`（只监听本机）。
- 不用时可以把防火墙规则也删掉：

```powershell
Remove-NetFirewallRule -DisplayName "AI Learning Lab"
```

### 换口令 / 让所有设备下线

```powershell
npm run auth:set-password                      # 只换口令，已登录设备继续有效
npm run auth:set-password -- --rotate-session  # 同时换会话密钥，所有设备要重新登录
```

改完要**重启** `start:lan` 才生效。

## 4. 数据在哪（只认这些）

| 路径 | 是什么 |
| --- | --- |
| `content/articles/*.md` | 笔记正文；文件名就是 id，frontmatter 的 `id` 必须一致 |
| `content/resources.json` | 资源收藏 |
| `content/tasks.json` | 学习任务 |
| `content/articles/.trash/` | 删掉的笔记（不是真删） |
| `content/.trash/` | 资源/任务删除留档；恢复时多出来的文件也进这里 |
| `backups/*.zip` | 备份（明文；不进 Git） |
| `.env.local` | 口令哈希 + 会话密钥（不进 Git、**不进备份**） |

- `content/articles/` 是独立私有仓库；不要把它提交到本项目（主仓库是公开的）。
- 笔记可以随时用别的编辑器改，刷新页面就生效；`resources.json` / `tasks.json` 最好在应用停掉时改，免得和界面写入抢。
- 删 `.trash/` 等于永久删除，没有第二层兜底（整库还能靠 `pre-restore` 快照回滚）。

## 5. 备份（最重要的一条）

1. 打开 `/backup` → 右上角「立即备份」。
2. 看到“备份已创建并通过自检”才算成功；列表里会多一份 `ai-lab-<时间戳>.zip`。
3. 需要时点「校验」再核一遍；点「下载」可以拷到 U 盘/另一块盘。
4. **备份是明文 zip**（里面就是你的笔记），别放公开同步盘、别发给别人。
5. `backups/` 不会自动清理。建议：大改之前手动备一份；只留最近几份，旧的删掉；另存一份到另一块盘。

不备份的东西：`.env.local`（换机后重设口令即可）、`content/.trash/restore-*`（恢复过程的二级副本）。

## 6. 恢复（会动 `content/`，按顺序来）

1. 确认没有别的设备正在编辑；最好先停掉手机上的页面。
2. 把要用的 zip 放进 `backups/`（从 U 盘恢复也一样，应用不接受上传）。
3. `/backup` → 找到那份 zip →「预览恢复」。
4. 看「新增 / 覆盖 / 相同 / 只在当前」四个数字；「只在当前」默认**不删**，要删就点「改为同时删除」（会移进 `.trash`，不是真删）。
5. 勾选“我知道这会改动 content/”，输入「恢复」，点「执行恢复」。
6. 应用会先建 `pre-restore-<时间戳>.zip` 快照，再写恢复日志、预检、原子写入、重扫校验；中途失败自动回滚。
   如果进程/系统在写入中途被强杀（日志 `backups/restore-journal.json` 会留下），**下次启动**会自动回到
   那份快照；在收尾完成前，新建/编辑/删除都会被暂停（页面会说明原因），避免把重启后的修改覆盖掉。
7. 自动回滚失败（比如快照被删/坏了）：`/backup` 会给出快照名。先把快照放回 `backups/` 再刷新重试；
   确认找不回来，就点「放弃这次恢复日志」（勾选 + 输入「删除」），之后不再自动回滚、写入恢复。
8. 想撤销这次恢复：在列表里对那份 `pre-restore-*` 点「回滚」。

## 7. 换电脑 / 重装

1. 新机器装 Node 24 / npm 11 / Git / Chrome。
2. `git clone https://github.com/danri-web/ai-learning-lab.git` → `cd` 进去 → `npm ci`。
3. 把旧机器的 `ai-lab-<时间戳>.zip` 放进新机器的 `backups/`（没有就新建）。
4. `npm run build` → `npm run start` → `/backup` 预览并恢复。
5. 恢复完检查 `/knowledge`、`/resources`、`/learning`。
6. 要手机访问，再跑一次 `npm run auth:set-password`（`.env.local` 不在备份里）。

## 8. 常见故障

| 现象 | 先做什么 |
| --- | --- |
| `npm` 报“无法加载 npm.ps1，因为在此系统上禁止运行脚本” | 用 `& 'D:\tools\nodejs\npm.cmd' run …`，不要改系统策略 |
| `start:lan` 直接退出 | 看提示：没 build 就 `npm run build`；没口令就 `npm run auth:set-password` |
| 3000 端口被占 | `Get-NetTCPConnection -LocalPort 3000 -State Listen` 找 PID，确认是自己旧进程再 `Stop-Process -Id <PID>` |
| 手机打不开，电脑本机能开 | 同一 Wi-Fi；防火墙专用网络放行；查 `node.exe` 的 Block 规则；地址别用 `127.0.0.1` |
| 口令肯定对却一直提示不对 | 看 `.env.local` 里是不是 `scrypt:...`（冒号分隔，不是 `$`）；不确定就重跑 `auth:set-password` 再重启 |
| 页面提示“有一部分内容读不出来” | 某个 `.md` 或 JSON 写坏了；应用会拒绝写入保护它。按提示的文件名改好或先移出 `content/` |
| 备份列表里某份标“损坏” | 不要手改 zip；换一份备份；重要数据先另存 |
| 跑 E2E 报“另一个 E2E 正在使用同一份副本” | 等上一轮结束；确有残留就按提示删锁文件（日常使用不会遇到） |

## 9. 安全边界（别越线）

- 默认只听 `127.0.0.1`；局域网是主动动作，只在**可信 Wi-Fi** 下开。
- 不做端口转发、不放到公网、不在不可信网络用；HTTP 不加密，口令和内容都是明文传输。
- 单用户模型：一个口令，没有账号/角色/多用户隔离。
- 备份是明文；`.env.local` 是密钥文件，两者都不要提交、不要外发。
- 不要为了“能连上”关掉整个防火墙，也不要为了测试关掉认证。
